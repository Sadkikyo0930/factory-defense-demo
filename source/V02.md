# V0.2 战场架构与验收记录

基线：63e832cb14fccf8e79888f6d5ad5fc8da6a699bc；独立分支 feature/v02-battlefield。此前源码包、构建和测试记录保留。

现状分析：旧版 1280×720 逻辑坐标，三个工位使用 x 坐标匹配，BD→POL→检测串联，不符合维修分流要求；设备约 120～170px、人员约 100px，路线上角色遮挡产品。新版本保留卡片、资格限制、单人工位及控制按钮，改为显式工位 ID 和路线节点。层级：地面0、物流1、方向2、设备3、产品4、提示5、人员6。

实际可执行的是演示 FA→修膜→PI→VI→OUT。修膜暂用 POL 资格，PI/VI 共用检测资格；这些只是明确的演示映射。BD 与 POL 设独立封闭工区，标明缺失工序；过判支路标明规则待完成。layout.ts 保存四条工艺序列，BD/POL/过判尚非可执行生产支路，切割/黑胶条件未实现。未虚构返修判定；返修通道和完整条件路由仍待后续实现。

设备采用正面图标式舞台表现，地面为正交平面，不使用含设备的斜俯视概念图作背景。当前属于战场布局原型，尚未达到完整卡通工厂环境的最终观感标准。背景仍需正式素材；此次没有新生成美术。

## 缺失资产
- 无设备、无道路标识的正交俯视工厂地面、墙体、门、护栏及仓储环境 PNG/tiles。
- 与俯视场景统一视角的全部设备：祛除、贴胶、BD、UV、撕POL、贴POL、脱泡、切割、黑胶、修膜、PI、VI、过判。
- 人员同视角 idle/walk/work 多帧；当前仅单张图的移动和等比脉动。
- FA/OUT 门、产品与托盘、排队槽、方向与堵塞提示精灵。
- 规格接口见 src/layout.ts assetSpec；人物60×96显示框、设备140×140显示框，等比适配。
