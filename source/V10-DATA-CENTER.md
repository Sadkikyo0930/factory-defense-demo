# V1.0 生产任务数据中心

从游戏顶部打开「生产任务数据中心」，点击「导入今日生产任务」，选择 V3.8 提取器生成的合并 JSON。核对 TV、MNT 和两个班次的数据后，点击「确认导入」。再次导入会同时替换期初、目标和计划。目标随当前页面任务保存，刷新后需要重新导入。旧版单日报仍可导入，计划显示「未导入」。

V3.8 的根节点为 `date / rows / targetBaseline / source / productionPlan`。目标来自 `targetBaseline.rows[].target`，期初来自 `rows[].today`。计划的 `dayQty / nightQty` 和 `expectedDay / expectedNight` 分别对应白班和夜班。换班时使用同一份期初和目标快照。工序存在数值但无法映射时，预览列出原始名称和位置，确认操作会保留上一份任务。没有直接预测投料的工序显示「无直接新增 NG」。

TV、MNT 先按尺寸归属，再对 MNT 的 NDF 按型号自动识别，优先级为 BAB 前缀、第 10 位、第 8 位。界面显示无法识别的型号和数量，并保留原任务直到来源可完整验证。其他需要 VI 的 MNT 预计产品进入 OC VI。计划使用各自班别的四类预测字段。FA、Disa 和未分区共享数据排除在维修任务外。共享黑胶分配为 TV 20%（四舍五入）、MNT 取余量，已分配的黑胶保持原值。

数据中心页头显示 `V1.0-rw38.3`。期初和目标分别按 Excel 指标单元格的 `mergeArea` 聚合。独立区域各自计数，同一区域冲突会列出两条 JSON 记录及其坐标。共享黑胶按区域识别后拆分。旧 V3.8 JSON 没有区域坐标时，仅在 `rw-win7-vbs` 来源包含本次确认的全部七组岗位及行号时应用该旧模板兼容规则。其他布局应从修订版 WIP 提取器重新导出。

## rw38.3 对账记录

根因是旧提取器把合并区域左上角值带入每个物理行，而旧网页按物理行累加。型号路线依赖手选，且网页重新由计划量推算预测，容易在取整边界偏离导出值。本次使用指标区域身份去重，并保留导出的班次预测后再按既有最大余数法分配整数片数。

| 工序 | 期初 | 目标 | 脱敏验收来源 |
|---|---:|---:|---|
| TV 祛除 | 12 | 123 | 49–50，模拟数值 |
| TV BD | 34 | 140 | 53–54，模拟数值 |
| MNT 祛除 | 31 | 133 | 51–52，模拟数值 |
| MNT BD | 56 | 150 | 55–56，模拟数值 |
| TV 黑胶 | 11 | 13 | 75–76，模拟数值 |
| MNT 黑胶 | 44 | 52 | 75–76，模拟数值 |
| MNT OC VI | 101 | 54 | 81–82 与 87–88，模拟数值 |
| TV PI | 14 | 16 | 两条各为 7／8 的独立模拟记录，均保留 |

浏览器对账跑了新旧 JSON、范围重复、旧模板、不同班次、二次替换、异常保留原任务、COF 和脱 POL。未找到原维修 SQL，型号优先级来自本次确认的业务规则，未与 SQL 实物对照。仓库内仅有 WIP 提取器，所以本次直接修订该提取器。使用 `tools/rw-report/Join-RW-Plan.ps1` 可将新版 WIP 和原合并文件里的同日计划组成新文件，旧版一键合并工具没有原件可修改。

## Windows Excel COM 验收

1. 在装有 Excel 且允许 Windows Script Host 的公司电脑运行 `cscript.exe //nologo Read-RW-WIP.vbs --merge-self-test`。只建立一个内存中的合成工作簿，期初 12、目标 123 应各读取一次，黑胶拆为 11／44。
2. 双击同一目录的 `Read-RW-WIP.bat`，确认启动行显示 `rw38.3`。打开有权限的日报并保存到获准目录。核对 49–50 等对应区间的 `mergeArea` 及各指标记录数量。
3. 在同一目录执行 `.\Join-RW-Plan.ps1 -WipPath .\rw-wip.json -PlanPath .\rw-combined-old.json -OutputPath .\rw-combined-new.json`，把文件名改为同日实际文件名。导入新文件并对照上表及两个班次的预测。

开发环境未注册 Excel COM，Windows Script Host 返回访问拒绝。PowerShell 合并脚本通过语法检查，实际执行被本机脚本策略阻止。真实区域读取、合并工具运行和公司日报尚待现场验收。

贴胶工作量按祛除和 BD 的期初及预计新增之和乘以所选班次 COF/片。脱 POL 工作量按撕 POL 和贴 POL 的期初及预计新增求和。脱 POL 的展示期初含撕 POL 期初和本 BU 的原始脱 POL 期初，目标为 0。引擎只在原始工序建立物理批次。只有 POL 汇总数时，整批从撕 POL 进入，之后继续贴 POL，免去手动拆分。同份日报同时有汇总和工序明细时要求核对，避免重复。

使用 `npm run build`、`node tests/v10-engine.cjs`、`node tests/v10-bu.cjs` 和 `node tests/v10-data-center.mjs` 验证。导入用例依据 `Rw wip.zip` 中的 V3.8 VBS 导出代码构造。附件只有提取工具和说明，实际生成的 JSON、真实日报和公司电脑仍待验收。
