# V0.7 帆软表头兼容修复

源码基线：cb0eeedafa86e60c9d884d6521d39f35cb46b0c6。修复分支：fix/v07-finereport-headers。

## 问题与改动

旧解析器只识别「岗位」等有限别名，前40行查找表头，且只向上4行查找WIP父级。它不支持「岗位明细」，也可能因SheetJS默认裁去开头空行，使原始合并区域的绝对坐标与二维数组错位。

本轮仅修改Excel解析/校验及相关测试：

- `src/report.ts`：统一NFKC字符规范化，去空格、换行、全角空格及零宽空格；支持岗位、岗位明细及原有工序/站点别名。岗位原始文本仍保留。
- 在既有20万单元格安全限制内扫描整个工作表，不再限定表头行号或「同一行」；按合并区域列范围匹配 WIP情况 → 今日实绩，可跨多层中间表头。垂直合并的叶子表头只计一个候选。
- 人员出勤下的今日实绩不能成为WIP；目标、昨日实绩和BAL均不作替代。跨过岗位数据的旧WIP父级不能复用于后续其他表段。
- 在岗位明细的左侧分组/多列区域中，根据实际映射岗位识别名称列；名称列有歧义则拒绝猜测。显式TV分组允许「BD」「PI」等短名，显式MNT分组不计入当前TV。空白分组仅在同一连续数据段沿用，遇其他分组/空行中断。
- 展开岗位、分组、今日实绩的合并行。相同白夜班快照去重；不一致数值仍要求人工确认。仅允许相邻的一对白/夜班补用缺失名称，不能把未知后续岗位连续填成同一岗位。
- 失败诊断包含实际工作表名/大小、识别表头及Excel坐标、今日实绩候选列、父级及拒绝原因；成功预览也显示选中岗位列、WIP列和数据起始行。继续使用现有textContent展示，不执行文件中的HTML。
- `src/report.worker.ts`：SheetJS从A1到实际末格读取，并保留空白行，保证!merges坐标不移位；仍为本地Worker解析、只读、无上传/COM、20MB/20万单元格/15秒边界保护。

TV POL20%拆分、黑胶直接取数、贴胶默认0、VI共享队列、初始OUT单列、取消失败保留模型等规则未改变。游戏场景、素材、岗位数量、动作、调岗及真实生产路线文件均无改动。
