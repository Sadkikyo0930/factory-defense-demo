# 网页日报导入与受限诊断

本轮基线：5199d9fbe4144ffd0a7bfe4fefadd7286bb6f446。

## 班组长操作

打开「导入日报」→选择 Excel →核对预览→确认替换初始 WIP。
标准 XLSX/XLS、XLSB、HTML 表格与 Excel XML 2003 由浏览器 Worker 本地读取；不上传文件，不需要 CMD、PowerShell、COM 或客户端安装。
保留现有 JSON 及手动初始 WIP 入口；旧 COM 工具保留为历史辅助功能，本次没有运行，也不作为日常操作要求。

失败时展开「文件头与格式诊断（仅本机）」，只显示原文件前 16 字节的十六进制、格式类型和当前/失败阶段。不显示文件正文、原文件名或工作表名称；日志不包含岗位数值。成功后的业务预览仍在本机显示岗位和值供用户确认。

## 本次检查与修正

- 现有二进制检测本来就检查 ZIP `50 4B 03 04`、OLE `D0 CF 11 E0 A1 B1 1A E1`，并检查 Office 目录/加密标记；不能仅凭扩展名认定格式。
- 新增固定长度 HEX 证据，避免 unknown 无从追查。OLE 中含 EncryptionInfo/EncryptedPackage 或 BIFF FilePass 时拒绝进入普通解码。
- 修复 `.json` 扩展名覆盖真实内容识别的错误；标准 XLSX 改名为 XLS/JSON 时仍按 XLSX 解析，未知二进制改名 JSON 不再伪装成 JSON。
- 解析失败不再建议每人运行本地工具；也不输出第三方解析器可能包含单元格内容的原始错误。
- 表头识别、合并表头、岗位/岗位明细归一化及原有 WIP 映射逻辑没有改动。始终只读 WIP 情况下的今日实绩，不以目标/昨日/BAL兜底。

**未提供出错的真实文件或其头字节，因此尚不能判断公司文件是加密、特殊封装、损坏、文本兼容格式，还是旧线上版本检测问题。** 标准合成文件的浏览器测试不能替代真实帆软验收。收到上述受限诊断即可先区分容器类型，无需传输生产内容。

## 一次集中部署的备选设计（仅设计，未实施）

若确认文件被公司文档加密/权限产品包装，或含当前 JS 解析库不支持的结构，改扩展名无法还原内部工作簿；当前解析器也没有解密或企业权限连接能力。不得绕过权限、猜密码或把文件发到公共服务。

首选由管理员在公司内网的帆软平台配置一个批准的 WIP 导出接口。仅导出固定字段 `{date,rows:[{name,today,group?}]}`，可让浏览器下载 JSON 后走现有确认入口；无第二套岗位映射，不需要在每台电脑安装软件。

如果平台无法直接导出该结构，可集中部署一个内网转换服务：接收由用户明确提交且有权限处理的文件，通过经公司批准的格式/权限组件读取。设置身份认证、TLS、上传大小与运行时限、临时文件及时清理，禁用宏和外部链接，不记录正文/岗位值，不传公共网络。服务只输出原始岗位和今日实绩，不在服务端重复拆分 POL 或分配共享 WIP。加密或权限不足时拒绝处理，由数据管理员提供批准的可读导出。

当前静态 GitHub Pages 不承载该内网服务。本轮没有实现上传接口、发送公司数据或更改部署。
